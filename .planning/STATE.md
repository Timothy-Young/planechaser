## What Was Done This Session (2026-07-31)

Full-app review, then a three-part hardening PR. Verified with `npm run
typecheck` (0 errors), `npm test` (79 passing), `npm run lint` (0 errors) and
`npm run build`.

### Part 1 — Production readiness (no schema impact)
- **Error boundaries**: added `error.tsx`, `global-error.tsx`, `not-found.tsx`.
  There were none, so any client throw white-screened a game in progress.
- **Viewport**: removed `maximumScale: 1` (WCAG 1.4.4 — players could not
  pinch-zoom card rules text).
- **PWA**: `manifest.ts`, a hand-rolled `public/sw.js` (cache-first for Scryfall
  art and audio, network-first navigations, never caches Supabase or `/api/*`),
  `offline.html`, and real PNG icons generated by `scripts/generate-icons.py`.
  Deliberately avoided `next-pwa` — its Next 16 compatibility was the open
  blocker recorded under Blockers/Concerns below, now moot.
- **CI**: `.github/workflows/ci.yml` runs typecheck, lint, unit tests and build.
  There was no CI at all, which is how two type errors survived since May.
- **Scripts**: added `test`, `test:watch`, `test:e2e`, `typecheck`, `icons`.
- **Orphaned tests**: `tests/multiplayer-session.spec.ts` imported from vitest
  but sat in Playwright's `testDir`, so *neither* runner executed it. Moved to
  `src/lib/game/multiplayer-session.test.ts` and fixed its two fixture type
  errors — unit tests went 65 → 68.

### Part 2 — Server-side achievements (migration 025)
- Any authenticated user could previously POST themselves the whole badge set,
  including `planar_dominion`. `grant_session_achievements()` is now a
  SECURITY DEFINER function that re-derives every criterion from
  `game_sessions` + `conquered_planes`; the INSERT policy on
  `user_achievements` is dropped, so the client cannot name a badge key.
- Anti-exploit guards (ACHV-02): session-scoped badges require ≥2 players and
  ≥3 minutes. `recordGameSession` now persists the real `started_at` so
  duration is meaningful, and returns the session id.
- `chaos_agent` now matches its own description ("Trigger chaos 10 times") —
  the old client check was a documented stand-in.
- Deleted `src/lib/achievements/evaluator.ts` rather than let two copies drift.
- Fixed a pre-existing bug where `router.push('/setup')` unmounted
  `AchievementToast` immediately, so earned badges were never actually seen
  (ACHV-03). Navigation now waits for the toast, with a bounded fallback timer
  so a stalled toast can't strand the player.
- Validated by running the migration against a throwaway Postgres 16 cluster
  with fixtures: 7 tests covering correct grants, idempotency, non-participant
  rejection, the solo-session guard, and the closed injection hole.

### Part 3 — Slimmed sync payload
- The host wrote the entire `GameState` on every action: the full deck as
  `PlaneCard[]` *plus* `stateHistory`, five undo snapshots each holding their
  own copy of that deck. Measured at **212.9 KB per write**, debounced 300ms,
  broadcast over Realtime to every spectator — close to Supabase Realtime's
  250 KB default payload limit.
- New `src/lib/game/wire-state.ts` projects to `deckIds` + `deckCount` + the
  1–2 cards actually on screen, and drops `stateHistory` (undo is host-only and
  reads sessionStorage). **212.9 KB → 4.2 KB, a 51× reduction.**
- Visible cards are inlined rather than rehydrated by id, so a host's *private*
  custom plane still renders for spectators.
- `fromWireState` also accepts the legacy full-`GameState` shape, so games in
  flight across the deploy keep rendering. 11 round-trip tests added.
